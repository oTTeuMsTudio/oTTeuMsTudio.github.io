World-building · UE 5.8

Official / built-in (best starting point)

Unreal Engine 5.8 leaned hard into world-building. This is the generic modular environment stack Epic is pushing. I am writing the clicks in order, in plain language, so I can actually do it.

The idea is simple: you write rules, the engine fills the world, and in 5.8 you can still move pieces by hand without breaking those rules. You do not start in Houdini. You start in Edit → Plugins.

The pieces

Five names. They stack. You do not turn all of them on on day one.

Core PCG Procedural Content Generation. Rule-based, modular worlds. Graphs of nodes that sample a surface, filter points, and spawn meshes. 5.8 lets you manually edit generated content without wiping the procedural rules.
Experimental PCG Primitives Ready-made subgraphs for roads, buildings, forests, parks, and similar pieces. Epic used this in the updated City Sample so you assemble a city from reusable PCG blocks instead of drawing every node from scratch.
Experimental Mesh Terrain 3D mesh terrain instead of classic heightfields. Overhangs, tunnels, cliffs, floating islands. Built to work with PCG and World Partition. Resolution can be dense where it matters and cheap in the distance.
Optional PCG Biome Core / Sample Biome-style scattering and layering on top of PCG. Volumes and splines paint “forest here, shore there.” The Sample plugin is a finished example world you can open and copy.
Study Updated City Sample Full PCG graphs plus the CitySamplePCG_demo plugin. Study it or reuse the blocks. The city is generated inside Unreal now — no external DCC required.
Do this first Enable PCG, PCG Primitives, and (if you want biomes) PCG Biome Core in Edit → Plugins. That trio is the generic modular env stack. Mesh Terrain and City Sample come after a graph actually spawns something.

Step 1 — Turn on the plugins

Plugins are off until you flip them. The editor will ask to restart. Save your work first.

  1. Open the Plugins window. In the Unreal Editor menu bar: Edit → Plugins. A search box sits at the top of that window.
  2. Search for PCG and enable these:
    • PCG Framework — the core system. Some lists call it Procedural Content Generation Framework. This is the one you cannot skip.
    • PCG Primitives — experimental. Ready-made subgraphs (roads, buildings, forests, parks). Turn it on.
    • PCG Geometry Script Interop — enable it if it appears. Biome Core depends on it.
    • PCG Biome Core — optional, experimental. Enable if you want biome volumes and layered scatter.
    • PCG Biome Sample — optional. Enable only after Biome Core. It is the example content, not the tool.
  3. Restart the editor when Unreal asks. Plugins do not load until that restart.
  4. Show plugin content in the Content Browser. Bottom-right of the Content Browser, open Settings (the gear). Check both:
    • Show Engine Content
    • Show Plugin Content
    Without those two ticks, PCG Primitives, Biome Core, and City Sample graphs stay hidden even though the plugins are on.
Experimental means Epic can change the plugin between versions. Fine for learning. If you later ship with Biome Core, Epic’s own docs say: copy the plugin into your project so a future engine update does not break your graphs.

Step 2 — Make a first PCG graph

A PCG graph is like a Blueprint, but for placing the world. Nodes in, points out, meshes spawn. One empty graph plus one volume is enough to prove the stack works.

  1. Create a folder in the Content Browser so this does not live in the root. Example: Content / PCG.
  2. Create the graph. Right-click in that folder. In 5.8 the menu is Procedural → PCG Graph (older videos still say PCG). Name it something obvious: PCG_FirstScatter.
  3. Optional: start from a template. If a template picker appears — a simple forest or showcase graph — you can initialize from that instead of a blank graph. Blank is clearer for learning. A template is faster if you just want to see trees.
  4. Open the graph (double-click). The editor looks like Blueprints: node palette, graph, Details. You will add nodes in step 4. Close it for a second and put it in the level first, so Generate has somewhere to run.

Step 3 — Put a PCG Volume in the level

The graph does nothing until an actor in the map runs it. The cheap actor is a PCG Volume: a box. Whatever sits inside that box is the work area.

  1. Place the volume. In the Place Actors panel (or Window → Place Actors), search PCG Volume. Drag it into the viewport. Or drag your PCG_FirstScatter asset into the level — Unreal often wraps it in a volume for you.
  2. Scale the box so it covers the ground you care about. Use the scale tool. Give it height in Z as well as width — a flat pancake misses tall meshes. Cover the whole graybox floor if you are still in a template map.
  3. Assign the graph. Select the volume. In Details, find the PCG component. Set Graph to PCG_FirstScatter.
  4. Press Generate on that same PCG component. Empty graph → nothing visible. That is correct. The volume is wired. Next you fill the graph.
World Partition Large maps should be World Partition levels (Open World template already is). PCG can partition with the world so only nearby cells generate. For the first scatter, ignore that. One volume, one graph, Generate.

Step 4 — The smallest graph that actually places something

Open PCG_FirstScatter. Think in three beats: sample the ground, thin the points, spawn a mesh. That is PCG.

  1. Sample the surface. Right-click in the graph and add Get Landscape Data (classic Landscape) or, if you already use Mesh Terrain, Mesh Partition Query then To Point. For a first test on the default landscape, Get Landscape Data is the easy node.
  2. Turn the surface into points. Add Surface Sampler (or To Point after a mesh query). Points are the invisible dots PCG will hang meshes on. In Details, raise point density a little if the preview looks empty — not a forest, just enough dots to see.
  3. Filter (optional but useful). Add a Transform Points if you need rotation, or a Density Filter / Bounds Filter to throw points away. Skip filters until you see a spawn. Empty output is usually “too much filtering,” not a broken plugin.
  4. Spawn. Add Static Mesh Spawner. In Details, add a mesh entry — any engine cube, rock, or tree. Connect the points into the spawner.
  5. Save the graph. Back in the level, select the PCG Volume and press Generate again. Meshes should appear inside the box. If they do, the stack works.

Debug trick: select a node in the graph and use the debug / inspect tools in the PCG toolbar. You want to see points before you blame the spawner. No points → the sampler never hit a surface. Points but no meshes → the spawner has no mesh assigned.

Step 5 — Edit generated content by hand (the 5.8 part)

Older PCG punished you: Generate again and your hand-placed tweaks vanished. 5.8 is built so you can keep both — the rules and the edits.

  1. In the PCG graph, select the Static Mesh Spawner (trees, rocks, whatever you spawned).
  2. In Details, enable Temporary Manual Editing Enabled (the wording is a bit awkward — it is the 5.8 manual-edit flag). A green marker on the node means it is on.
  3. Back in the viewport, select spawned instances. Move them, rotate them, delete the ones that clip a path. You are editing the generated result, not rebuilding the graph.
  4. Generate again after a graph change. The procedural rules still run. Your manual edits are meant to survive that, which is the whole 5.8 point: the world is modular and still art-directable.

Use this when PCG puts a tree in a doorway. Do not use it to place the whole forest by hand — that fights the tool. Rules for the field. Hands for the exceptions.

Step 6 — PCG Primitives (assemble instead of inventing)

Once a cube spawns, stop drawing every node yourself. Primitives are ready-made subgraphs. Epic used them to block a city from reusable pieces: roads, buildings, forests, parks.

  1. In the Content Browser, with plugin content visible, open /PCGPrimitives/Primitives. That folder is the toolbox: shape creation, subdivision, splines, polygons, spawning.
  2. Open /PCGPrimitives/Examples next. Those are working graphs, not empty nodes. A forest or park example is the right second graph to copy, not a 18-graph city.
  3. In your own graph, right-click and add a primitive as a subgraph (same idea as a Blueprint function). Feed it a spline or a shape. Get spawn points or a footprint out. Chain primitives instead of one giant graph.
  4. Typical city-shaped chain, in English:
    • Draw a closed boundary (the city or the district).
    • Cut it with a couple of arterial roads.
    • Subdivide into blocks.
    • Build the road network from those cuts.
    • Turn leftover polygons into lots, parks, or forest.
    • Spawn buildings on the lots.
    That is what PCG Primitives are for. You do not need MCP or an LLM for this — the subgraphs work standalone.
Where to look Primitives: /PCGPrimitives/Primitives. Examples: /PCGPrimitives/Examples. If the folders are missing, the plugin is off, or Show Plugin Content is still unchecked.

Step 7 — Mesh Terrain (only if you need 3D ground)

Classic Landscape is a heightfield: one height per X/Y. No cave, no overhang, no floating island. Mesh Terrain is a 3D mesh with modifiers, designed to talk to PCG and World Partition. It is experimental. Skip it until scatter on a normal landscape feels boring.

  1. Enable extra plugins in Edit → Plugins:
    • MeshPartition — the core.
    • Mesh Terrain Mode — the toolbar mode.
    • PCG MeshPartition Interop — PCG read/write.
    • MeshPartitionWater — only if you need water bodies on it.
    Restart again.
  2. World Partition has to be on for the map. Open World maps already have it. A basic blank map may not — Mesh Terrain will refuse to create. Convert the level with Tools → Convert Level (World Partition) if you hit that wall, or start from the Open World template.
  3. Switch the editor mode to Mesh Terrain (same mode bar as Landscape / Foliage / Modeling).
  4. Use the Create tab. Make a rectangle (or another base). That actor is a mesh partition — the ground is now a mesh, not a heightmap.
  5. Shape it with the Modifiers tab: sculpt, noise, remesh, booleans for tunnels and overhangs. Modifiers stack. They are non-destructive — you can peel one off later.
  6. In PCG, do not use Get Landscape Data on this ground. Use Mesh Partition Query, then To Point to scatter, or Write if the graph should carve or erode the mesh. Same priority layer on Query and Write so the graph does not feedback-loop itself.

Use Mesh Terrain when the world needs a cave, a cliff you can walk under, or an island that is not a flat displacement. For a top-down graybox, Landscape is still enough.

Step 8 — PCG Biome Core (layer the biomes)

Biomes are “this volume is forest, that spline is shore.” They sit on top of PCG, they are not a second engine. Enable PCG Biome Core (and Sample if you want the demo map).

  1. Content Browser paths after plugins + Show Plugin Content:
    • /All/EngineData/Plugins/PCGBiomeCore
    • /All/EngineData/Plugins/PCGBiomeSample
  2. Easiest start: open BiomeSampleLevel from /PCGBiomeSample/Maps. Walk the map. Note the BP_PCGBiomeCore volume and the biome volume / spline actors inside it. That level is the manual.
  3. In your own map:
    1. Drag BP_PCGBiomeCore from /PCGBiomeCore/Blueprints into the level.
    2. Scale its volume to the coverage you want. Generation stays inside that box.
    3. Drag BP_PCGBiomeVolume or BP_PCGBiomeSpline so it overlaps the ground and sits inside the Core volume.
    4. On the biome actor, set a name, a color, and a priority (the definition). Higher priority wins where volumes overlap.
    5. Point it at a generator (a small PCG graph that samples the world and outputs points — Core ships TPL_BiomeCore_Generator as a template) and at meshes to spawn on those points.
  4. Save. The biome should refresh and scatter inside the volume. Add a second volume with different meshes to see two biomes meet. Overlapping splines blend if you give them a blend range.

Landscape is optional for Biome Core. You can run it on Mesh Terrain too. For a first biome, one volume of trees is enough.

Step 9 — Study the City Sample (do not start here)

The 5.8 City Sample is the finished exam, not the first homework. It is a full PCG city: mesh terrain island, curved roads, lots, buildings, parks, outer forest. The original 5.0 city was Houdini. This one is Unreal only, plus a plugin you can steal from.

  1. Get the project from Fab / the Epic Games Launcher samples, for Unreal Engine 5.8. Open it in 5.8, not an older editor.
  2. Inside it, find the CitySamplePCG_demo plugin. That plugin is the reusable part: PCG graphs and assets to recreate the city. Also look at PCG Primitives — the city is built out of those blocks.
  3. Open the main PCG demo level (the large procedural city, not the old Big_City_LVL traffic demo). Expect a world-partitioned map, uneven terrain, three road types (artery, collector, local), and hand-placed landmarks: a hero tower and a small Central Park.
  4. Pause PCG while you poke graphs. Editor Preferences → enable the PCG pause control, then pause. Otherwise every node tweak rebuilds a city.
  5. To regenerate from zero: Tools → PCG Framework → Cleanup All PCG components. Then generate graphs in Outliner order. Names are the order:
    • PCG_1_1_Terrain — island from a spline, Mesh Terrain.
    • PCG_1_2 / 1_3 — background buildings and mountains.
    • PCG_2_* — tower and park footprints (exclusion zones).
    • PCG_3_1_1_Districts → roads → highways → lots.
    • PCG_3_2_* — ground, leftover plazas, parking.
    • PCG_3_3_* — buildings, rooftops.
    • PCG_4_* — tower and park visuals.
    • PCG_5_* — shore, outer forest.
    Change a low number, everything after it rebuilds. Change rooftops, the island does not.
  6. Edit the Spline Guides (terrain shape, city boundary, arteries, highways, high-rise zone) if you want a different city. The graphs read those splines. That is the art-directable part.
What this sample is not It is a PCG building lesson, not the playable Matrix-city traffic demo. No mass AI, no traffic lights. You can walk and fly. Copy graphs and primitives into your project. Do not try to finish a game inside this map on week one.

What to do this week

Order matters more than plugins. One spawned mesh beats a city you never generated.

01 Plugins, restart, Show Plugin Content PCG Framework + PCG Primitives. Biome Core if you want it. That is the stack.
02 Empty graph + PCG Volume + one mesh Get Landscape Data → Surface Sampler → Static Mesh Spawner. Generate. See a cube. Then you know it works.
03 Turn on manual editing Move or delete a few instances. Generate again. Confirm 5.8 kept the edit.
04 Open one Primitive example /PCGPrimitives/Examples — a forest or park, not the full city. Duplicate it into your folder and swap meshes.
Later Biome Sample, then City Sample, then Mesh Terrain Read other people’s graphs before you invent caves. Mesh Terrain last, unless the graybox already needs a tunnel.
