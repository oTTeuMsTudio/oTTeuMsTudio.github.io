Systems programming

How you build one like this

Bevy owns the window, the GPU, and the tick. You write the editor, the runtime, and the zip the homepage downloads — same argument as oTTeCAD below, no garbage collector.

That landing is renzora.com: a name, Bevy 0.19, two ways in, a screenshot of the editor. Renzora is a 3D engine and a visual editor on Bevy. You unzip windows-x64.zip and run it. The same World plays in the runtime. Every system is a plugin you can add or strip. That is the product — not a crate you cargo run once.

You do not beat Unreal by starting here. You learn the loop Unreal already solved, with Bevy doing the metal: window, device, scene (ECS), tick, present. Then you split the binary: editor for authors, runtime for the game. System-level Rust is the language for that loop. There is no garbage collector. Each entity, each panel, each swapchain image has one owner. Bevy’s scheduler will not run two systems that both write the same component in the same frame — that is the borrow checker for the tick.

The systems you actually write

You do not start by writing an ECS, a C-ABI, or gaussian splats. Bevy’s ECS is the point of “based on Bevy.” Renzora is plugins on that App, then two binaries, then a Release. A spinning cube in a viewport you own is already an engine. Modeling, marketplace, and VR come years later.

01 App and plugins App::new().add_plugins(DefaultPlugins). Window, input, GPU, assets. Your engine is more plugins on that App — Renzora’s cut.
02 ECS Entity is an ID. Components are structs. Systems are functions. The World owns the rows. Editor and runtime share it.
03 Editor Viewport, hierarchy, inspector, gizmos, G / R / S. Wireframe / Solid / Material / Rendered. This is what a Renzora screenshot is.
04 Runtime The game binary — no editor, no dock. Same plugins, same scene. Renzora also runs it with --server.
05 Export templates my-runtime-<platform>.zip — runtime only. The editor fetches these so you can package for a machine you are not sitting at.
06 GitHub Releases Tag a build. Actions zips windows-x64.zip (editor + runtime). Nightlies off main. Unzip and run — no compile.

The World owns the frame

Memory is the argument, same as the modeler below. A C++ engine leaks when a node outlives its mesh. A garbage-collected engine pauses when the heap is walked mid-frame. Bevy makes the story compile: the World owns every entity. A Query<&mut Transform> is an exclusive borrow of that column. Two systems that both need it will not overlap. Drop frees the World — no GC scan.

The editor and the runtime are two main functions on the same plugins. The editor adds hierarchy, inspector, and gizmos. The runtime does not. That split is how Renzora ships a 24 MB editor zip and a smaller game.

Start with DefaultPlugins and a spinning cube. Your EnginePlugin next. An editor viewport after the cube is yours. Do not begin with C-ABI plugins, a marketplace, or forking the renderer.

Crate map

One crate until it hurts. Then a workspace so the editor and the runtime stay two binaries on one World. This is the Renzora-shaped cut, not a clone of their crate names. 

my-engine/
  Cargo.toml                 # [workspace]; pin bevy = "0.19"
  crates/
    engine/                  # World, scene, gameplay plugins
    editor/                  # viewport, hierarchy, inspector, gizmos
    runtime/                 # game binary — no dock, no editor
  .github/workflows/
    release.yml              # tag → platform zips on Releases
  README.md
  LICENSE-MIT
  LICENSE-APACHE             # same dual license as Bevy and Renzora
  .gitignore                 # /target, /dist, *.pdb

Ship it like Renzora’s Releases page

Source on GitHub is half the job. Renzora’s Releases page is the other half: unzip, run the editor, no cargo. Install Rust from rustup.rs so you can build. Install GitHub CLI for gh release create.

  1. Scaffold: cargo new my-engine --lib. Pin bevy = "0.19". Split into editor and runtime binaries when the cube is yours. On Windows, dynamic_linking on the editor crate keeps iteration faster.
  2. Push the source. README says how to cargo run -p editor, which Bevy version you pin, what GPU it needs. MIT OR Apache-2.0, like Bevy and Renzora.
  3. Stage a dist folder: editor exe + runtime exe + a few assets. Zip it windows-x64.zip. One platform is enough for the first tag. Renzora later adds Linux, macOS, wasm, and runtime-only templates.
  4. Tag and attach. git tag r1-alpha1, push the tag, then gh release create with the zip. A GitHub Action can do that on every tag — and a nightly job off main, the way Renzora names r1-alpha7-nightly-07sep26.

Later: manifest.json and SHA256SUMS beside the zips. Later: my-runtime-windows-x64.zip as an export template. Later: a wasm editor, the way every Renzora nightly refreshes the playable build. Do not start there. The modeler below is that discipline applied to mesh topology instead of an editor World.

Rust

Writing my own 3D modeler

I am building oTTeCAD in Rust system-level code — mesh topology, GPU viewport, tools, and undo I own. Not a plugin, and not a script on top of someone else's editor. The same workbench compiles to WebAssembly and runs here.

This is the hard path. System-level Rust sits next to C and C++: you talk to the GPU, lay out bytes, and keep a mesh alive without a runtime holding your hand. There is no garbage collector. If a vertex buffer, an undo stack, or a selection set is allocated, I own it until it is dropped. The borrow checker will not compile until that story is true — no dangling pointers, no use-after-free, no two writers on the same memory.

Memory management is the argument of the language. Each value has one owner. Other code may borrow it for a limited time. Lifetimes are the compiler proving those borrows do not outlive the owner. That is slower to write than Python, JavaScript, or a high-level engine script. It is also why this editor can run next to the metal — native on the desktop, WebAssembly here — without leaking, and without a GC pause walking the heap.

oTTeCAD is a desktop modeler. Open this page on a computer with WebGPU or WebGL2 (Chrome, Edge, or recent Firefox).
